# Development progress

## Verified public baseline

Scope: source-driven conversion of the documented OpenSCAD subset to standalone Autodesk Fusion Python scripts. The current baseline has 93 offline tests, 19 native cases and four toothbrush mesh comparisons. Detailed evidence is linked from testing.md and toothbrush-validation.md.

Publication uses a fresh Git history containing source, fixtures, tests, tools and sanitized documentation/evidence. Private prompts, local work logs, machine paths, runtime output and environment files are excluded. Numeric evidence and source hashes are retained; paths in evidence identify relative artifacts rather than a developer machine.

## Next checkpoint: simpler native geometry

Preserve the verified baseline before experimenting. Recognize geometric regularity from source-derived data without hard-coding project/module/parameter names. Start with rounded helical geometry while retaining its radial/Z section, phase, pitch and end taper. Add offline recognition tests, run isolated native probes, measure face/feature count and compare shape against the source. Keep arbitrary polyhedron support explicit. Publish updates only after independent review and relevant verification; no physical fit claim follows from CAD checks.

## 2026-10-16: publication and recognition experiment

- Public main/tag `v0.1.0` point to root commit `219ca0b`. GitHub visibility and remote SHA were independently queried after pushing. The prior private checkout/history remain separate.
- Work continues on `work/analytic-geometry`. `helical.py` recognizes ordered circular radial/Z sections from numeric vertices/connectivity, recovers pitch/phase and retains every radius and source profile vertex. It rejects malformed types, inconsistent winding/connectivity, nonuniform pitch and changed vertices. It intentionally supports only the local source Z axis and regular sampling; it is not yet used by the converter.
- Independent review found coordinate-dependent tolerance and invalid-type exceptions; regression tests now cover both.
- Isolated Fusion 2705.1.30 circle-profile experiments produced healthy 3-face solids from 51/63 selected sections, replacing 23042/28802 source faces. Raw-thread comparisons FAILED the existing 0.5% volume/symmetric-difference gates: body volume 1.0885%, cap 1.0438%; surface deviations 0.034074/0.034226 mm. Both meshes remained closed, single-component, with matching tested section counts. These measurements do not establish whole-model fidelity or fit.
- Next experiment preserves the source 24-sided polygon section in each Loft. Fix shared SketchPoint anchors: fixing separate lines left 49 unshared sketch points and an underconstrained first profile. The probe now explicitly shares/fixes its 24 vertices. Runtime scripts own and close only their new documents, restore the previously active document, and write partial failure evidence.
- Polygon-Loft helix-1 passed the existing comparison gates: 26 native faces, 0.001694 mm bounds error, 0.034596 mm sampled bidirectional surface error, 0.190373% volume error and 0.389398% symmetric difference. Its two measured section loop counts and single closed component match the source. This is an isolated raw-thread result, not full model validation.
- Polygon-Loft helix-2 also passed: 26 faces, 0.001725 mm bounds error, 0.034631 mm sampled surface error, 0.148145% volume error and 0.345939% symmetric difference. Native generation plus STL export took about 129/199 seconds. The combined MCP request exceeded its 300-second transport deadline while Fusion continued; both completed report entries and exported meshes were subsequently verified, and a read-only query confirmed zero remaining test documents. Avoid starting another mutation while an apparently timed-out native script is still running.
- A final conservative recognition guard rejects changing vertex phase/order between rings, because skipping such sections could change the source polygon twist. Recognition still passes both real thread meshes. Shared points preserve each selected polygon exactly, while the Loft interpolates between sections.
