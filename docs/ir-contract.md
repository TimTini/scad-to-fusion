# Frontend ↔ generator contract

`Expr` dataclass fields: `value` (float/int/bool/str), `text` (symbolic OpenSCAD-style expression using global parameter names), `deps` (frozenset of global binding names). Literal booleans use true/false in text. Numeric constants use Python-compatible formatting. Binary expressions are fully parenthesized in `text` so Python-AST consumers retain SCAD grouping. Vectors/lists are Python lists of Expr or nested lists (not Expr wrapping a list).

`Node` dataclass fields: `op: str`, `args: dict[str, Expr|list|dict]`, `children: list[Node]`, `line: int`. Nodes are normalized geometry calls retaining symbolic arguments, plus `union`, `difference`, `intersection`, and `for`. Root is union (possibly a single child). Geometry arguments use canonical SCAD names: square size/center; circle r (normalize d); cylinder h/r1/r2/center; cube size/center; translate v; rotate a and optional v; scale v; linear_extrude height/center/twist/scale; offset r. Preserve $fn in primitive args as fn. Reject unknown arguments explicitly. Module invocations expand generically by binding their actual arguments to formals while retaining global expression names. Blocks become union.

`Program` dataclass fields: `parameters: dict[str, Expr]`, `geometry: Node`, `source_name: str`, `rebuild_parameters: frozenset[str]` (default empty). Parameters include all top-level numeric/boolean bindings except $special variables; Expr.text is the defining expression (literal for base input). In geometry, a global binding references its name via Expr.text, preserving dependencies even if its defining value is derived. Module local names are substituted into the actual argument expressions. Generation-time `if` and ternary conditions add their global dependencies to `rebuild_parameters`; changing one of those values requires rebuilding the generated structure. Ternaries evaluate only the selected branch, whose symbolic Expr.text/deps are retained. `assert` conditions are validation checks and do not add rebuild metadata.

`compile_source(source: str, overrides: dict[str, object]|None=None, filename: str='<string>') -> Program` in frontend.py. Overrides apply to existing top-level base bindings; unknown overrides rejected. Derived references follow override values; original expressions otherwise preserved. Assert failure and unsupported constructs raise `ScadError(ValueError)` with filename:line and readable message. No Python eval of untrusted source.

`for` preserves metadata and expanded children. `args['bindings']` is a list of dicts, each containing `name: str`, `values: list[Expr]`, `start: Expr|None`, `step: Expr|None`, `end: Expr|None`. Range bindings have start/step/end; list bindings use None. children contain all expanded body nodes in SCAD Cartesian loop order. Index references are substituted by literals, not Fusion user parameters. A for with list [-1,1] and 2D children remains useful to the geometry backend as union. Empty loop children produce no geometry. `args['probes']` is a list of diagnostic/template `Node` values, one per binding only when the loop is `pattern_safe`; each probe evaluates the original loop body with every binding at its first expanded value, except its selected binding: a range uses `start + step` even when that value is outside a one-item range, while a list uses its second value when available and otherwise its first. Unsafe loops have `probes=[]` so hypothetical values cannot trigger validation or arithmetic outside the rendered domain. Probes preserve symbolic global expressions and literal loop-index substitution, do not add rendered children, and wrap multiple body nodes in a `union`; an empty loop has `probes=[]`. `args['template']` is one additional diagnostic `Node` with the same body shape, compiled using numeric placeholder bindings whose text is `__loop_<name>` and whose dependencies are empty. The template is metadata only and never adds rendered children; an empty or non-numeric loop may use `None`. `args['pattern_safe']` is false when template generation cannot safely represent the loop structure, including loop-dependent `if`/ternary branches, assertions, nested loops, or user module calls. A template keeps nonlinear placeholder expressions (for example, `__loop_x * __loop_x`) so the backend can reject them instead of misclassifying them as affine. A generator may recognize regular range loops for native Pattern only after checking the template; others are fixed at generation and reported rebuild.

Top-level variables in the source are declarative: resolve forward references at that scope, detect dependency cycles, keep lexical module parameters/local assignments. Implement the actual tray constructs and small independent fixtures; reject unsupported semantics rather than silently treating SCAD as sequential Python. Scope extensions beyond that require evidence/tests.

The generator infers dimensions from geometric usage and expression dependency equations; parameter names are not semantic tags. Helpers converting dataclasses to JSON belong to generator, not frontend.

2026-10-16 extension: user functions, `let`, indexing, vector arithmetic and nested comprehensions evaluate generically. String and array top-level bindings are generation settings, excluded from numeric Fusion parameters; overrides retain their JSON types. `len` materializes a literal count and marks its input dependencies for regeneration. Assert-only loops emit no geometry.

`polygon.args.points` is a nested list of coordinate Expr. `rotate_extrude.args.angle` is dimensionless degrees, default360, with polygon/planar children. Native interpretation maps profile X to radius and Y to model Z before applying the enclosing Frame. Native angular surfaces are analytic.

`polyhedron.args.points` and `.faces` contain evaluated numeric arrays to bound output size. `rebuild_dependencies` contains all mesh dependencies; `coordinate_expressions` contains first/last vertex coordinates plus middle samples introducing dependencies or expression structures for dimension inference. It is metadata, not extra geometry. The native builder requires one closed connected consistently oriented shell and planar nondegenerate faces, shares vertices/edges, corrects overall orientation and adds the solid as a BaseFeature. Mesh coordinates change through regeneration. The generator expands rebuild dependencies to upstream scalar inputs and reports per-parameter `update` policy.
